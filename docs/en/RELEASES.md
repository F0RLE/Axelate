# Axelate Releases

> Current release workflow for this repository.
> This is operational documentation, not future roadmap.

## Branches

- `nightly` is the active development branch.
- `main` is the release-ready branch.
- Dependabot targets `nightly`.
- Release tags should be created from the commit that is meant to ship.
- Release tags must point to a commit that is already reachable from `main`.

## CI

`Strict CI` runs on:

- pushes to `main`
- pushes to `nightly`
- pull requests targeting `main`
- pull requests targeting `nightly`
- manual dispatch from GitHub Actions

The CI gate checks frontend linting, formatting, type/build, bundle size, tests, Rust clippy, Rust check, Rust tests, and audit reporting.

## Local Release Check

Before tagging a release, run:

```bash
npm run verify
```

If `verify` fails, do not create a release tag.

## Version Rule

The release tag must match all project manifests:

- `package.json`
- `src/package.json`
- `src-tauri/Cargo.toml`

Example:

```text
tag: v0.1.5
manifest version: 0.1.5
```

Pre-release tags are allowed when the manifest versions match:

```text
tag: v0.1.6-alpha.1
manifest version: 0.1.6-alpha.1
```

## Create A GitHub Release

Create and push a tag from the release commit:

```bash
git tag v0.1.5
git push origin v0.1.5
```

GitHub Actions then runs `Release Build`.

The release workflow:

- checks the tag format
- checks manifest versions
- checks that the tagged commit is reachable from `main`
- installs frontend dependencies
- runs frontend and Rust audits
- builds Windows Tauri bundles
- verifies release hardening
- generates `SHA256SUMS.txt`
- creates or updates the GitHub release assets

## Manual Release Rerun

Use the `Release Build` workflow in GitHub Actions and provide an existing `v*` tag.
Manual runs are for rerunning a failed release, not for releasing an untagged branch.

## Current Limits

- Windows is the current release target.
- Code signing is not configured in this repository yet.
- Release notes are generated by GitHub release assets and tag metadata, not a custom changelog pipeline.
