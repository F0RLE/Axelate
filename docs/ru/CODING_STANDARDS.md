# СТАНДАРТЫ КОДИРОВАНИЯ И ТРЕБОВАНИЯ (ИНЖЕНЕРНЫЕ СТАНДАРТЫ AXELATE)

**Версия документа:** 2.1.0  
**Последнее обновление:** 2026-01-24
**Статус:** ОБЯЗАТЕЛЬНО

Этот документ устанавливает строгие инженерные стандарты для проекта Axelate. Любой код, нарушающий эти принципы, не будет принят для слияния и потребует немедленной доработки. Мы придерживаемся философии **"Zero Broken Windows"** и **"Clean Code"**.

---

## 1. Политика очистки и "De-AI" (НУЛЕВАЯ ТОЛЕРАНТНОСТЬ)

**Наш код должен выглядеть как результат работы высококвалифицированных инженеров, а не LLM.**

### 1.1. Запрет артефактов генерации
- Строго запрещены комментарии вида: `Generated by`, `AI suggestion`, `As an AI I think`, `Copilot fix`, `Here is the code`.
- Запрещены "водяные знаки" LLM в стилистике (например, избыточные комментарии очевидных вещей: `// Returns void`).

### 1.2. Профессиональная терминология
- "Разговорный" стиль в комментариях и документации запрещен.
- ❌ *Плохо:* `"This thing tries to grab data"`
- ✅ *Хорошо:* `"Attempts to retrieve payload with exponential backoff strategy"`
- ❌ *Плохо:* `"Fixing the bug with user login"`
- ✅ *Хорошо:* `"Patched race condition in authentication flow during session rehydration"`

### 1.3. Принцип осмысленности
- Если код выглядит как шаблонный (boilerplate), он должен быть абстрагирован.
- Если комментарий не объясняет, *почему* было принято архитектурное решение (бизнес-контекст или ограничения платформы), он должен быть удален.

## 2. Архитектура и принципы проектирования

### 2.1. SOLID & GRASP
- **SRP (Single Responsibility):** Модуль отвечает за одного актора. Если класс управляет и рендерингом, и сетью — это нарушение.
- **OCP (Open/Closed):** Классы открыты для расширения, но закрыты для модификации. Используйте наследование и композицию.
- **LSP (Liskov Substitution):** Подтипы должны быть заменяемы базовыми типами.
- **ISP (Interface Segregation):** Много специализированных интерфейсов лучше, чем один универсальный.
- **DIP (Dependency Inversion):** Модули верхнего уровня не должны зависеть от модулей нижнего уровня. Оба должны зависеть от абстракций (интерфейсов/трейтов).

### 2.2. Управление состоянием
- **Единый источник истины (Single Source of Truth).** Избегайте дублирования состояния в разных частях системы.
- **Однонаправленный поток данных (Unidirectional Data Flow).** Данные текут в одном направлении. Состояние меняется только через определенные точки.
- **Используйте `UIStateInterface`** для глобального состояния UI.

### 2.3. Изоляция побочных эффектов (Side Effects)
- Чистые функции (Pure Functions) должны быть в приоритете.
- Все операции ввода-вывода (I/O) должны быть явно изолированы в слоях сервисов (`services/`).
- Документируйте побочные эффекты в JSDoc с помощью тега `@sideeffect`.

### 2.4. Событийно-ориентированная архитектура
- Используйте `EventBus` для межмодульного взаимодействия.
- Именование событий: `domain:action` (например: `page:change`, `module:download:complete`).
- Всегда отписывайтесь от событий в методах очистки/удаления (cleanup/destroy).

## 4. Фронтенд (TypeScript / Высокая производительность)

### 4.1. Типизация (STRICT MODE)

**Конфигурация TypeScript:**
```json
{
  "compilerOptions": {
    "strict": true,
    "noFallthroughCasesInSwitch": true,
    "target": "ESNext",
    "module": "ESNext"
  }
}
```

**Правила:**
- ❌ **НИКАКИХ `any`:** Использование `any` запрещено. Используйте `unknown` с Type Guard.
- ✅ **Строгие проверки на null:** Все поля, которые могут быть `null`/`undefined`, должны обрабатываться явно (`?.`, `??`).
- ✅ **Интерфейсы важнее типов:** Используйте `interface` для публичных контрактов.
- ✅ **Явные типы возврата:** Публичные методы должны иметь явно указанный тип возвращаемого значения.

```typescript
// ❌ Bad
function processData(data: any) {
    return data.value;
}

// ✅ Good
function processData(data: unknown): string | null {
    if (isValidData(data)) {
        return data.value;
    }
    return null;
}

function isValidData(data: unknown): data is { value: string } {
    return typeof data === 'object' && data !== null && 'value' in data;
}
```

### 4.2. Интерфейсы и типы

**Соглашения об именовании:**
- Интерфейсы: префикс `I` для важных контрактов (`IApp`, `IModule`, `IConfigField`)
- Алиасы типов: без префикса, PascalCase (`LogEntry`, `ModuleDownloadState`)
- Дженерики: одна заглавная буква (`T`, `K`, `V`) или описательное имя (`TPayload`)

```typescript
// ✅ Well-defined interface
export interface IApp {
    id: string;
    name?: string;
    nameKey?: string;
    desc?: string;
    descKey?: string;
    icon?: string;
    type?: 'api' | 'local';
    installed?: boolean;
    repoUrl?: string;
    config_schema?: Record<string, IConfigField>;
}
```

### 4.3. Производительность и жизненный цикл

**Манипуляции с DOM:**
- Используйте `DocumentFragment` для массовой вставки элементов.
- Избегайте "Layout Thrashing" (чередование чтения и записи свойств DOM).
- Используйте `requestAnimationFrame` для визуальных изменений.
- ❌ Никогда не используйте `setInterval` для визуальных эффектов.

**Управление памятью:**
- **ОБЯЗАТЕЛЬНО:** Все подписки (`addEventListener`, `Observer`, `WebSocket`, `EventBus.on`) должны быть удалены в методах очистки.
- Утечка памяти — это **блокирующая P0 ошибка**.
- Используйте `debounce`/`throttle` для обработчиков `onInput`, `onResize`, `onScroll`.

```typescript
// ✅ Proper cleanup
class ModuleUI {
    private unsubscribers: (() => void)[] = [];

    public init(): void {
        const unsub = eventBus.on('page:change', this.handlePageChange);
        this.unsubscribers.push(unsub);
        
        window.addEventListener('resize', this.handleResize);
        this.unsubscribers.push(() => window.removeEventListener('resize', this.handleResize));
    }

    public destroy(): void {
        this.unsubscribers.forEach(fn => fn());
        this.unsubscribers = [];
    }
}
```

### 4.4. Безопасность

- **Предотвращение XSS:** Использование `innerHTML` для пользовательского контента запрещено. Используйте `DOMPurify.sanitize()` или `textContent`.
- **Никаких секретных данных:** Никаких API-ключей и секретов на клиенте. Используйте `axelateAPI.secureStorage`.
- **Соответствие CSP:** Никаких инлайновых скриптов. Все скрипты подключаются через модули.

```typescript
// ✅ Safe content insertion
import DOMPurify from 'dompurify';

const sanitizedHtml = DOMPurify.sanitize(userInput);
element.innerHTML = sanitizedHtml;

// Or even better:
element.textContent = userInput;
```

### 4.5. Лучшие практики Async/Await

```typescript
// ❌ Bad: Unhandled promise
async function loadData() {
    const data = await fetchData();
    return data;
}
loadData(); // Promise ignored!

// ✅ Good: Proper error handling
async function loadData(): Promise<Data | null> {
    try {
        const data = await fetchData();
        return data;
    } catch (error) {
        console.error('[Module] Failed to load data:', error);
        globalThis.showToast?.('Failed to load data', 'error');
        return null;
    }
}

// ✅ Good: Top-level await or .catch()
loadData().catch(console.error);
```

## 5. Бэкенд (Rust / Безопасность и многопоточность)

### 5.1. Обработка ошибок (Panic-free zone)

- **Проброс Result:** Функции возвращают `Result<T, E>`, а не вызывают панику.
- **Структурированные ошибки:** Используйте `thiserror` для библиотек, `anyhow` для приложений.

**Политика Unwrap:**
- `unwrap()` / `expect()` разрешены ТОЛЬКО:
  1. В тестах (`#[cfg(test)]`)
  2. При инициализации `const` или `lazy_static`/`once_cell`
  3. Когда инвариант математически доказан (с комментарием `// SAFETY: ...`)
- Во всех остальных случаях — `match` или `?`.

### 5.2. Многопоточность и асинхронность

- **Неблокируемость:** Никогда не блокируйте поток Tokio (`std::thread::sleep`).
- Используйте `tokio::time::sleep` или `tokio::task::spawn_blocking` для тяжелых вычислений.
- **Разделение состояния:** Минимизируйте использование `Mutex`. Рассмотрите паттерн Actor через каналы `mpsc`.

### 5.3. Стиль кода (Idiomatic Rust)

- Используйте Clippy как закон: `cargo clippy -- -D warnings`
- **Паттерн Newtype:** Типы-обертки вместо примитивов (`struct UserId(String)`).
- Документация через `///` для публичных API.

## 8. Стандарты тестирования

### 8.1. Фреймворк для тестирования
- **Vitest** — основной фреймворк для тестирования
- Конфигурация в `vite.config.ts`

### 8.2. Структура тестов

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest';

describe('ComponentName', () => {
    beforeEach(() => {
        // Setup/cleanup
    });

    describe('methodName', () => {
        it('should do X when Y', () => {
            // Arrange
            const input = createTestInput();
            
            // Act
            const result = component.method(input);
            
            // Assert
            expect(result).toBe(expected);
        });

        it('should handle edge case Z', () => {
            // ...
        });
    });
});
```

### 8.3. Соглашение об именовании тестов
- Файлы: `ComponentName.test.ts`
- Describe: имя компонента/модуля
- It: `должен [ожидаемое поведение] когда [условие]`

### 8.4. Моканье (Mocking)

```typescript
// Use vi.fn() for mocks
const handler = vi.fn();
eventBus.on('page:change', handler);

eventBus.emit('page:change', { pageId: 'home' });

expect(handler).toHaveBeenCalledTimes(1);
expect(handler).toHaveBeenCalledWith({ pageId: 'home' });
```

### 8.5. Требования к покрытию
- Сервисы (`services/`): минимум 80% покрытия
- Утилитарные функции: 100% покрытия
- UI компоненты: тестирование критической логики

- Ссылки на задачи (если есть)

```typescript
private async _handleDeleteModule(app: IApp, category: string): Promise<void> {
```

## 16. Паттерны архитектуры сервисов

### 16.1. Сервисы-одиночки (Singleton)

Все глобальные сервисы реализуются как синглтоны с явным экспортом:

```typescript
// ✅ Correct Singleton pattern
class EventBusImpl {
    private readonly listeners: Map<string, Set<EventHandler>> = new Map();
    
    // ... methods
}

// Singleton export

```

**Implementation Pattern:**
```typescript
export class MyFeatureService {
    private static instance: MyFeatureService;
    private constructor() {}

    public static getInstance() {
        if (!this.instance) this.instance = new MyFeatureService();
        return this.instance;
    }
}
```

**Singleton Services List:**
| Сервис | Экспорт | Цель |
|---------|--------|---------|
| `EventBus` | `eventBus` | Межмодульное взаимодействие |
| `ErrorHandler` | `errorHandler` | Глобальная обработка ошибок |
| `LoggerService` | `logger` | Централизованное логирование |
| `AIBridge` | `aiBridge` | Абстракция провайдеров ИИ |
| `ChatFileHandler` | `chatFileHandler` | Управление файлами чата |

```typescript
}
```

## 32. Стратегии кэширования

### 32.1. LocalStorage с TTL
Используйте обертку для кэширования данных с ограниченным сроком жизни.
```typescript
interface CachedData<T> {
    value: T;
    timestamp: number;
    ttl: number;  // milliseconds
}

function setWithTTL<T>(key: string, value: T, ttlMs: number): void {
    const data: CachedData<T> = {
        value,
        timestamp: Date.now(),
        ttl: ttlMs
    };
    localStorage.setItem(key, JSON.stringify(data));
}

function getWithTTL<T>(key: string): T | null {
    const raw = localStorage.getItem(key);
    if (!raw) return null;
    
    try {
        const data: CachedData<T> = JSON.parse(raw);
        const isExpired = Date.now() - data.timestamp > data.ttl;
        
        if (isExpired) {
            localStorage.removeItem(key);
            return null;
        }
        
        return data.value;
    } catch {
        return null;
    }
}
```

        error: Error,

## 36. Чистый код и минимализм (Дзен Axelate)

### 36.1. Политика "Никакого мертвого кода" (Zero Tolerance)

**Мы не храним мусор.** Код должен быть либо живым, либо удаленным.

- **Запрещено:** Закомментированные блоки кода (кроме специфических примеров). Git — это ваша история; вам не нужно хранить старые куски "на всякий случай".
- **Запрещено:** Неиспользуемые интерфейсы, переменные или импорты.
- **Запрещено:** Методы, которые никогда не вызываются.

```typescript
// ❌ Bad: Dead code graveyard
// function oldWay() {
//    return true;
// }

// ❌ Bad: Speculative interface (nothing uses this)
interface IFutureFeature {
    teleport(): void;
}

// ✅ Хорошо: выполняется только то, что работает
```

### 36.2. YAGNI (You Aren't Gonna Need It)

Не реализуйте функции, типы или абстракции "на будущее". Обновляйте стандарты по мере возникновения необходимости, а не раньше.

- Не создавайте `BaseManagerAbstractFactory`, если вам просто нужна функция.
- Не добавляйте поля в интерфейсы "потому что они могут пригодиться позже".

### 36.3. Лаконичность (Меньше — значит больше)

**Мы предпочитаем компактный код.** Излишняя многословность создает шум и затрудняет сканирование кодовой базы.

- **Минимизируйте количество строк (LOC).** Если логика может быть выражена в 1 строке, не растягивайте ее на 5.
- **Тернарные операторы — это нормально.** Используйте их для условного присвоения значений без временных переменных.
- **Fail fast.** Возвращайте управление как можно раньше, чтобы избежать глубокой вложенности.

```typescript
// ❌ Bad: Unnecessary verbosity
let status;
if (user.isActive) {
    status = 'Active';
} else {
    status = 'Inactive';
}

// ✅ Good: Concise
const status = user.isActive ? 'Active' : 'Inactive';
```

### 36.4. Правило бойскаута

**"Всегда оставляй кодовую базу чище, чем ты ее нашел."**

- Если вы открыли файл, чтобы исправить ошибку, и увидели опечатку в комментарии — исправьте ее.
- Если вы видите переменную с именем `x` — переименуйте ее в `timeoutMs`.
- Если вы видите мертвый код — удалите его.
- **Небольшие постоянные улучшения предотвращают накопление технического долга.**

## 37. Паттерн Core Orchestrator

Класс `Core` служит центральным оркестратором для всего фронтенд-приложения.

### 37.1. Цель
- **Единая точка входа:** Все сервисы создаются и инициализируются через `Core`.
- **Внедрение зависимостей (DI):** Сервисы получают ссылку на `Core` для взаимодействия между собой.
- **Последовательность загрузки (Boot Sequence):** Детерминированный порядок инициализации гарантирует готовность зависимостей.

### 37.2. Структура

```typescript
// src/modules/core/core.ts
class Core {
    // Сервисы создаются в конструкторе
    public readonly tauriProvider: TauriProvider;
    public readonly logger: LoggerService;
    public readonly state: StateService;
    public readonly i18n: I18nService;
    public readonly eventBus: EventBus;
    // ... остальные сервисы

    constructor() {
        // 1. Создание сервисов в порядке зависимостей
        this.tauriProvider = new TauriProvider();
        this.logger = new LoggerService();
        this.state = new StateService(this);
        // ...
    }

    async init(): Promise<void> {
        // 2. Инициализация в определенном порядке
        await this.state.loadState();
        await this.i18n.init();
        await this.templateLoader.init();
        // ... инициализация UI
    }
}

// Register for debugging
document.addEventListener('DOMContentLoaded', () => {
    const coreInstance = new Core();
    coreInstance.init().catch(console.error);
    (globalThis as Window & { core: Core }).core = coreInstance;
});
```

### 37.3. Паттерн доступа к сервисам

```typescript
// ✅ Внутри сервиса, у которого есть ссылка на Core
class SomeService {
    constructor(private readonly _core: Core) {}

    doSomething(): void {
        this._core.logger.info('[SomeService] Действие');
        this._core.state.set('key', value);
        this._core.eventBus.emit('some:event', payload);
    }
}

// ✅ Доступ через globalThis (для отладки/легаси)
window.core.logger.info('Сообщение отладки');
```

### 37.4. Правила последовательности загрузки
1. **TauriProvider** — первый (нативный мост)
2. **LoggerService** — второй (инфраструктура логирования)
3. **StateService** — загрузка сохраненного состояния
4. **I18nService** — переводы
5. **TemplateLoader** — инъекция HTML
6. **UI Services** — после загрузки шаблонов
7. **GlobalBridge** — экспорт API в последнюю очередь

## 38. Паттерн GlobalBridge Facade

`GlobalBridge` отделяет внешний глобальный API от оркестратора `Core`.

### 38.1. Цель
- Предоставить доступ к основным функциям через `globalThis` для легаси-кода и обработчиков `onclick` в HTML.
- Группировать API по доменам (Модули, I18n, Окна, Навигация).
- Обеспечить типобезопасный интерфейс через `IGlobalBridgeProperties`.

### 38.2. Реализация

```typescript
// src/modules/core/boot/GlobalBridge.ts
class GlobalBridge {
    constructor(private readonly _core: Core) {}

    init(): void {
        this._exposeCoreGlobals();
    }

    private _exposeCoreGlobals(): void {
        const win = globalThis as unknown as IGlobalBridgeProperties;

        // Управление модулями
        win.downloadModule = (id, url) => this._core.moduleService.download(id, url);
        win.deleteModule = (id) => this._core.moduleService.delete(id);

        // I18n
        win.t = (key, def, ...args) => this._core.i18n.t(key, def, ...args);
        win.setLanguage = (lang) => this._core.i18n.setLanguage(lang);

        // Управление окнами
        win.minimizeWindow = () => this._core.windowService.minimize();
        win.hideToTray = () => this._core.windowService.hideToTray();

        // Навигация
        win.showPage = (id, btn, isInit) => this._core.navigation.showPage(id, btn, isInit);

        // Toast API
        win.showToast = (msg, type, dur, title, id) => 
            this._core.appUI.showToast(msg, type, dur, title, id);
    }
}
```

### 38.3. Соглашение об именовании

| Домен | Префикс | Пример |
|--------|--------|---------|
| Модули | `downloadModule`, `deleteModule` | `globalThis.downloadModule('gpt', url)` |
| I18n | `t`, `setLanguage` | `globalThis.t('ui.button.save', 'Save')` |
| Окна | `minimizeWindow`, `hideToTray` | `globalThis.minimizeWindow()` |
| Toast | `showToast` | `globalThis.showToast('Success', 'success')` |

### 38.4. Использование в HTML


```
    └── {module}Utils.ts    # Вспомогательные функции
```

### 41.2. Обязанности контроллера

```typescript
// src/modules/chat/chat.ts
class ChatController {
    private readonly _service: ChatService;
    private readonly _ui: ChatUI;

    constructor() {
        this._service = new ChatService();
        this._ui = new ChatUI();
        this._init();
    }

    private _init(): void {
        this._bindEvents();
        this._exposeGlobals();
    }

    private _bindEvents(): void {
        // Привязка событий DOM
        document.getElementById('chat-send')
            ?.addEventListener('click', () => this.sendChat());
    }

    private _exposeGlobals(): void {
        // Поддержка легаси
        (globalThis as unknown as Record<string, unknown>).sendChat = 
            () => this.sendChat();
    }

    async sendChat(): Promise<void> {
        const text = this._ui.getInputText();
        const response = await this._service.send(text);
        this._ui.renderResponse(response);
    }
}
```

### 41.3. Service vs UI Separation

| Слой | Ответственность | Пример |
|-------|---------------|---------|
| **Service** | Вызовы бэкенда, бизнес-логика, трансформация данных | `ChatService.send()`, `ModuleService.download()` |
| **UI** | Запросы к DOM, рендеринг, анимации | `ChatUI.renderMessage()`, `SettingsUI.showTab()` |
| **Controller** | Координация, привязка событий, поток состояния | `ChatController.sendChat()` |

### 41.4. When to Use Controller

- **С контроллером:** Сложные модули с несколькими UI-компонентами и сервисами (Чат, Настройки).
- **Без контроллера:** Простые модули, где достаточно пары Service + UI (Отладка, Мониторинг).

```typescript
    private _streamBuffer = '';
    private _onChunk: ((chunk: string) => void) | null = null;

    async init(): Promise<void> {
        // Подписка на события стриминга
        await globalThis.__TAURI__.event.listen<string>(
            'ai:thought:chunk',
            (event) => {
                this._streamBuffer += event.payload;
                this._onChunk?.(event.payload);
            }
        );

        await globalThis.__TAURI__.event.listen<void>(
            'ai:thought:done',
            () => this._finalizeStream()
        );
    }

    async sendMessage(
        text: string,
        source: MessageSource = 'chat',
        attachments: Attachment[] = []
    ): Promise<string> {
        this._streamBuffer = '';

        const request: IChatRequest = {
            provider: this._activeProviderId,
            model: this._selectedModel,
            api_key: this._apiKey,
            messages: this._history,
            // ...
        };

        await globalThis.__TAURI__.core.invoke('send_chat_message', { request });
        return this._streamBuffer;
    }
}
```

```rust
fn setup_system_tray(app: &tauri::App) -> Result<(), Box<dyn std::error::Error>> {
    let show_item = MenuItem::with_id(app, "show", "Открыть", true, None::<&str>)?;
    let quit_item = MenuItem::with_id(app, "quit", "Выход", true, None::<&str>)?;

    TrayIconBuilder::new()
        .menu(&Menu::with_items(app, &[&show_item, &quit_item])?)
        .on_menu_event(|app, event| {
            match event.id.as_ref() {
                "show" => {
                    if let Some(window) = app.get_webview_window("main") {

                        window.set_focus().ok();

                        create_main_window(app);
                    }
                }
                "quit" => {
                    IS_QUITTING.store(true, Ordering::Relaxed);
                    app.exit(0);
                }
                _ => {}
            }
        })
        .build(app)?;
```

## 45. Паттерн Наблюдатель (Observer) (Pub/Sub сервисы)

Сервисы, испускающие данные со временем, реализуют паттерн Наблюдатель (Observer) для обеспечения слабой связанности.

### 45.1. Интерфейс

```typescript
interface IObservable<T> {
    subscribe(callback: (data: T) => void): void;
    unsubscribe(callback: (data: T) => void): void;
}
```

### 45.2. Implementation

```typescript
// src/modules/monitoring/services/MonitoringService.ts
export class MonitoringService {
    private listeners: StatsCallback[] = [];

    public subscribe(callback: StatsCallback): void {
        if (!this.listeners.includes(callback)) {
            this.listeners.push(callback);
        }
    }

    public unsubscribe(callback: StatsCallback): void {
        this.listeners = this.listeners.filter((cb) => cb !== callback);
    }

    private notifyListeners(stats: ISystemStats): void {
        this.listeners.forEach((cb) => {
            try {
                cb(stats);
            } catch (err) {
                console.error('[MonitoringService] Ошибка слушателя:', err);
            }
        });
    }
}
```

| `stopMonitoring()` | Остановить передачу, очистить слушателей |
| `destroy()` | Полная очистка, удаление всех подписчиков |

```typescript
public captureError(error: Error, context?: string): void {
    const errorInfo: IErrorInfo = {
        message: error.message,
        stack: error.stack,
        context,
        timestamp: Date.now(),
    };

    // Логирование с ротацией
    this._errorLog.push(errorInfo);
    if (this._errorLog.length > this._maxLogSize) {
        this._errorLog.shift();
    }

    // Оповещение подписчиков
```

```typescript
// Обертка для асинхронных функций
public async wrapAsync<T>(fn: () => Promise<T>, context?: string): Promise<T | undefined> {
    try {
        return await fn();
    } catch (error) {
        this.captureError(error instanceof Error ? error : new Error(String(error)), context);
        return undefined;
    }
}

// Обертка для обработчиков событий
public safeHandler<T extends Event>(
    handler: (event: T) => void,
    context?: string
): (event: T) => void {
    return (event: T) => {
        try {
            handler(event);
        } catch (error) {
            this.captureError(error instanceof Error ? error : new Error(String(error)), context);
        }
    };
}
```

```rust
pub fn start_monitoring(app: AppHandle, interval_ms: u64) {

    }
```

```typescript
    const installedModules = await this._tauri.invoke<IModule[]>('get_modules');

    const mergeSchema = (list: IApp[]) => {
        list.forEach((app) => {

            }
        });
    };

    mergeSchema(this._appData.ai);
```

## 57. Параметризованный перевод (I18n)

Интернационализация с интерполяцией параметров и цепочкой фолбэков (fallback chain).

### 57.1. Функция перевода

```typescript
// src/modules/core/services/I18nService.ts
public t(
    key: string, 
    defaultText: string = '', 
    params: Record<string, unknown> = {}
): string {
    let text = this._translations[key] || defaultText || key;

    // Интерполяция параметров: {name} → значение
    for (const [k, v] of Object.entries(params)) {
        text = text.replace(`{${k}}`, String(v));
    }
    return text;
}
```

### 57.2. Цепочка отката (Fallback Chain)

```typescript
public async loadTranslations(lang: string): Promise<void> {
    let base: Record<string, string> = {};
    let target: Record<string, string> = {};

    // 1. Всегда загружаем английский как базу
    base = await this._fetchTranslations('en');

    // 2. Загружаем целевой язык, если он отличается
    if (lang !== 'en') {
        target = await this._fetchTranslations(lang);
    }

    // 3. Слияние: целевой язык переопределяет базу
    this._translations = { ...base, ...target };
    this._currentLang = lang;
    document.documentElement.lang = lang;
}
```

### 59.2. Фильтрация на основе паттернов

```typescript
private processLogs(newLogs: ILogEntry[]): ILogEntry[] {
    const filteredLogs = newLogs.filter((log) => {
        const msg = (log.message || '').toUpperCase();
        const src = (log.source || '').toUpperCase();

        // Пропуск шума AI-сервисов
        const isBotSource = 
            src.includes('CHATSERVICE') ||
            src.includes('AIBRIDGE');

        // Пропуск обычных HTTP ошибок
        const isAIError =
            msg.includes('ERROR 429') ||
            msg.includes('ERROR 400') ||
            msg.includes('QUOTA');

        return !(isBotSource || isAIError);
    });

    this.logs.push(...filteredLogs);
    this.lastTimestamp = newLogs.at(-1)?.timestamp ?? this.lastTimestamp;
    return filteredLogs;
}
```

## 60. Делегирование Service-to-Bridge

Тонкий слой сервиса, который делегирует сложные операции глобальным мостам (bridges).

### 60.1. Паттерн

```typescript
// src/modules/chat/services/ChatService.ts
export class ChatService {
    public async sendMessage(
        text: string,
        history: IChatMessage[],
        attachments: IChatAttachment[],
    ): Promise<IChatResponse> {
        // Валидация ввода
        if (!text?.trim() && !attachments?.length) {
            return { ok: false, error: 'Сообщение пустое' };
        }

        // Проверка доступности моста
        const aiBridge = (globalThis as any).aiBridge;
        if (!aiBridge) {
            return { ok: false, error: 'AI Bridge не инициализирован' };
        }

        // Проверка активности провайдера
        if (!aiBridge.isActive?.()) {
            return { ok: false, error: 'Модуль ИИ не запущен' };
        }

        // Делегирование мосту
        try {
            const response = await aiBridge.sendMessage(text, 'chat', attachments);
            
            // Обработка префикса ошибки
            if (response.startsWith('Error: ')) {
                return { ok: false, error: response.replace('Error: ', '') };
            }
            
            return { ok: true, message: response };
        } catch (e) {
            return { ok: false, error: e.message };
        }
    }
}
```

### 60.2. Преимущества
- **Разделение ответственности:** Логика модуля отделена от внутреннего устройства AI.
- **Тестируемость:** Легко мокать `aiBridge`.
- **Нормализация ошибок:** Единый формат `IChatResponse`.
- **Защитные условия (Guard Clauses):** Быстрый отказ с понятными сообщениями об ошибках.

### 60.3. Когда использовать
| Кейс | Подход |
|----------|----------|
| Простой IPC | Прямой вызов `TauriProvider.invoke()` |
| Сложный AI/стриминг | Делегирование в `AIBridge` |
| Состояние между модулями | Доступ через `GlobalBridge` |
